## Forks, ports and reuse

You're welcome to fork Sleepium, port it to other Minecraft versions (backports and newer versions alike) or loaders,
and publish your build on CurseForge, Modrinth or anywhere else. It's under LGPL-3.0, which allows all of this. What the
licence asks in return:

- keep your changed source open under LGPL-3.0, with the licence files (`LICENSE` and `COPYING`) included;
- say that your version is modified, and keep the existing copyright notices.

A few requests on top, so players can tell builds apart:

- **Name it as unofficial**, for example "Sleepium (unofficial 1.21.4 port)", and link back to this repository.
- **Change something.** Platforms don't allow plain re-uploads of someone else's mod; link to the official pages
  instead.
- **Mod id:** a straight port to another Minecraft version can keep `sleepium` (configs and packs keep working); a fork
  with different features should use its own id.
- **Exactness:** Sleepium's promise is that it changes nothing the game computes. Please call your build exact only if
  it passes the exactness checks - the tools are in this repository (`tools/suite.py`, `tools/box_suite.py`).

If you'd like to look after the official project while I'm away, open an issue and say so.

---

A performance engine for modded Minecraft that changes nothing the game computes. Every optimisation is checked
against vanilla: the same world after thousands of ticks (block and entity hashes), the same frame bit for bit.

Next to other optimisation mods it works with them, not against them: where another mod already changes the same code,
Sleepium steps aside there and says so in the log.

> **Using C2ME? Use Sleepium 1.1.4 or newer, and check your world.** Before 1.1.4, Sleepium together with C2ME (or
> another mod that saves chunks on its own threads) could save chunks with parts missing. That was my bug, found and
> fixed in 1.1.4. Signs of it: `No key palette in MapLike[{}]` in the log, chunks that look hollow or do not appear.
> 1.1.4 saves correctly (tested: a world generated with C2ME, the game restarted, every chunk read back without an
> error), but it cannot restore data that was never written. If you played with C2ME on an older version, regenerate
> the broken chunks - delete them with MCA Selector, or the region files of that area in `saves/<world>/region` - or
> start a new world. Anything built in those chunks is lost when they regenerate.

## Help wanted: checking Sleepium against mods

Sleepium lets a block entity sleep only when it can prove from the code that skipping its tick changes nothing,
and every release is checked against vanilla scene by scene. Mods are where that proof is hardest: a mod's machine
may keep its state in its own objects, use its own inventories and energy, or tick in ways our tests have not seen
yet. This release found and closed one such gap (machines whose tick goes through an interface) by placing every
block of 13 popular mods and reading what the analysis made of them. Next we want an automatic check that works for
any mod: every machine fed and drained through the standard item / energy / fluid connections, put to sleep and
woken in every way a player can, and compared with vanilla tick by tick.

If you know a mod whose machines behave differently with Sleepium, know a good way to test this kind of thing, or
want to help run such checks on your pack, please open an issue on GitHub or leave a comment - we will be grateful.
A link to the mod or the pack is enough: we download mods only from their official pages.

## Install

Put the jar for your Minecraft version and loader into `mods/`. Nothing else is required; it runs on clients and
servers. Settings: *Options → Sleepium...*

## How this repository is organized

- **Each supported version has its own branch**, named after the Minecraft version and the loader
  (`1.21.1-neoforge`, `1.20.1-forge`). A branch is a complete mod for that version: its own build, its own tests, a
  README about what is special there. There is no shared core and no preprocessor: what a branch holds is exactly
  what runs.
- **This branch (`main`) is the front page**: this README, the documentation for all versions, the changelog.
- **Versions no longer supported** move to `eol/<minecraft>-<loader>` branches, with a tag of their last release; they
  stay readable and buildable. The table above lists them too.
- A change made for one version is brought to the others by the maintainers, or marked as specific to that version.

Want to contribute? See [CONTRIBUTING.md](CONTRIBUTING.md) - in short: a pull request to the branch of your version.
